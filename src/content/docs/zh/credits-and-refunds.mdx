## 积分流水

每次余额变动都是 `credit_transaction` 表里的一行，`user.credits` 存当前总数。改积分一定要走 `src/lib/credits.ts`，直接改库会让两边对不上，每天的 `ledger.check` 任务会把差异报出来。

| 函数 | 用途 | 余额不足时 |
| --- | --- | --- |
| `grantCredits` | 加积分 | 不涉及 |
| `spendCredits` | 消费积分 | 返回 `ok: false`，不做任何改动 |
| `deductCredits` | 退款、拒付时扣回 | 照扣，余额可以变成负数 |

```ts
const result = await spendCredits({ userId, amount: 5, note: "my-feature" });
if (!result.ok) return Response.json({ error: "insufficient_credits" }, { status: 402 });
```

每行都有一个 `reason`：

| 类型 | 含义 |
| --- | --- |
| `signup_bonus` | 注册赠送 |
| `purchase` | 购买积分包 |
| `subscription` | 订阅周期发放 |
| `trial` | 试用期发放 |
| `spend` | 使用付费功能 |
| `refund` | AI 调用失败退回 |
| `clawback` | 退款、拒付扣回，或退款申请冻结 |
| `restore` | 解除冻结或拒付赢回后还回 |
| `admin` | 管理员手动调整 |

## 幂等

`refId` 在整张流水表里唯一。相同 `refId` 已存在时，`grantCredits` 和 `deductCredits` 什么都不做，返回 `false`。

```ts
await grantCredits({ userId, amount: 100, reason: "purchase", refId: `order_${orderId}` });
```

Webhook、对账和重试处理同一笔付款时用的是同一个 `refId`，不管谁先到、跑几次，积分都只发一次。

`spendCredits` 用条件更新保证并发安全：只有余额够扣时这行才会被更新。

## 退款规则

规则在 `src/config/refunds.ts`：

```ts
export const refundRules = {
  packDays: 14,       // 积分包：付款后多少天内可申请
  maxUsedRatio: 0.5,  // 用掉超过这个比例不能自助申请
  perAccount: 1,      // 每个账号自助退款次数
  minAmount: 50,      // 最低退款金额（分）
};
```

- 订阅只能退当期，且订阅必须还有效。
- `perAccount` 统计待审核、处理中和已退款的申请，被拒、失败、已撤销的不算。
- 被拒绝或失败过的付款，用户不能再次申请；自己撤销的可以。

不符合规则的用户看不到申请按钮。他们联系客服后，你到支付平台后台退款，webhook 会自动扣回积分。

## 退款公式

退款按未用积分算，不按时间算。否则用户第一天用掉大半积分，还能退回大半的钱。计算在 `src/lib/credit-math.ts` 的 `computeRefund`：

```text
剩余 = 当初发放 + 关联的扣回和还回
未用 = min(当前余额, 剩余 - 发放后用掉的)
金额 = floor(实付 × 未用 / 当初发放)
积分 = ceil(当初发放 × 金额 / 实付)
```

金额向下取整，积分向上取整，取整不会让用户多退钱。发放之后用掉的积分，保守地算在这笔付款头上。

举个例子，$5.00 买了 100 积分，用掉 20：

```text
未用 = 80
金额 = floor(500 × 80 / 100) = 400 分
积分 = ceil(100 × 400 / 500) = 80
```

## 申请的状态

| 状态 | 含义 | 积分 |
| --- | --- | --- |
| `pending` | 已提交，等待审核 | 冻结 |
| `processing` | 已批准，等待平台结果 | 冻结 |
| `refunded` | 平台确认已退款 | 已扣回 |
| `rejected` | 管理员拒绝 | 已还回 |
| `canceled` | 用户撤销 | 已还回 |
| `failed` | 平台调用失败或退款被拒 | 已还回 |

### 冻结

用户**提交申请**时，可退的积分就从余额里扣出，金额也在这一刻定下来，审核期间不能再用这部分积分。

- 批准时按定好的金额退款，不重新计算。
- 用户可以撤销待审核的申请，积分立即还回。
- 申请全额退当期订阅时，Pro 会立即暂停；撤销或被拒绝后恢复。

### 各平台批准后做什么

| 平台 | 批准时的操作 |
| --- | --- |
| Stripe | 按 PaymentIntent 退款，订阅同时关闭自动续费 |
| Waffo | 建商户退款工单（自动通过），订阅同时取消续费 |
| Creem | 不会自动退款，管理员到 Creem 后台操作，webhook 到达后结单 |
| Mock | 立即完成 |

平台调用失败时，冻结自动解除，申请变成 `failed`。修好问题后，管理员可以点 **Retry** 重试。

重试时按现在还没用掉的积分重新计算，金额只会变少，余额不会被扣成负数。如果解冻的积分已经用完，重试会停止并返回 `nothing_left`。

如果之后退款没成功（比如 Waffo 工单被拒），点 **Release** 把积分还给用户。收到 Waffo 的 `refund.failed` 事件时会自动处理。

## 扣回

平台发来退款或拒付时，`clawbackGrant` 从当初发放的那笔积分里扣回：

- 部分退款按比例扣回，向上取整。
- 累计扣回不超过这笔付款发放的积分。
- 申请时已冻结的积分算在扣回里。平台实际退多或退少时，差额补扣或还回。
- 余额不够也照扣。余额为负时不能使用付费功能，充值补上后恢复。
- 找不到对应的发放记录时，服务端会打一条 `[clawback]` 告警。

如果你直接在支付平台后台退款，webhook 也会结掉这笔付款上未完成的申请，不会被再批准一次、重复退钱。

### 订阅

当期订阅款全额退回时，Pro 立即结束，状态变为 `refunded`，因为三家平台退款后都不会自动结束订阅。部分退款和退更早月份的款都保留 Pro。只有新一期付款成功或拒付赢回才能恢复。
